# pr-mon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a Textual TUI that monitors open PRs across GitHub repos, shows merge readiness and blocking reasons, flags repos needing attention, and merges/updates PRs from the keyboard.

**Architecture:** Pure data layers (`models`, `tracker`, `config`, `state`) under an async GraphQL client (`github`), consumed by a Textual app (`app`, `screens`). The app polls on a timer, feeds results to the tracker, and re-renders.

**Tech Stack:** Python 3.13, uv (packaged app, `src/` layout), textual, httpx, unittest, ruff (dev only), Makefile.

**Spec:** `docs/superpowers/specs/2026-09-16-pr-mon-design.md`

## Global Constraints

- All imports at module level, never inside functions.
- Tests use `unittest` (async tests use `unittest.IsolatedAsyncioTestCase`); never pytest.
- Use `uv` for everything (`uv add`, `uv run`); no bare venv / pip.
- Runtime deps: `textual`, `httpx` only. Dev deps: `ruff` only.
- github.com only. Auth token from `gh auth token`.
- Config: `$XDG_CONFIG_HOME/pr-mon/config.toml` (default `~/.config/pr-mon/config.toml`).
- State: `$XDG_STATE_HOME/pr-mon/state.json` (default `~/.local/state/pr-mon/state.json`).
- PRs: newest 50 open by `CREATED_AT` DESC; first 20 check contexts per PR.
- Poll interval default 60s; CHECKING re-poll after 5s, max 3 times.
- Keys: `A` add repo, `D` remove repo, `r` refresh, `q` quit, `enter` actions, `m` merge, `u` update branch, `esc` close. Merge sub-choice keys: `s` squash, `m` merge, `r` rebase.
- Merge method preference order: SQUASH, MERGE, REBASE.

### Task 2: models — parsing, status, reasons

**Files:** Create `src/pr_mon/models.py`, `tests/fixtures.py`, `tests/test_models.py`.

**Produces:**
- `class Status(StrEnum)`: `DRAFT, CHECKING, CONFLICT, FAILING, PENDING, BEHIND, BLOCKED, READY`
- `BLOCKED_STATUSES: frozenset[Status] = {CONFLICT, FAILING, BLOCKED}`
- `class MergeMethod(StrEnum)`: `SQUASH="SQUASH", MERGE="MERGE", REBASE="REBASE"`
- `@dataclass(frozen=True) Check(name: str, state: str)` — state normalized: CheckRun not COMPLETED → `PENDING`, else its conclusion; StatusContext → its state.
- `Check.failed` property: state in `{FAILURE, ERROR, CANCELLED, TIMED_OUT, ACTION_REQUIRED, STARTUP_FAILURE}`; `Check.pending`: state in `{PENDING, EXPECTED, QUEUED, IN_PROGRESS, WAITING, REQUESTED}`.
- `@dataclass(frozen=True) Reason(text: str, level: str)` — level in `"error" | "warning" | "info"`.
- `@dataclass(frozen=True) PullRequest(id, number, title, url, author, created_at, is_draft, head_ref, base_ref, head_ref_id: str | None, head_repo: str | None, mergeable, merge_state, review_decision: str | None, check_state: str | None, checks: tuple[Check, ...], checks_total: int)` with properties `status -> Status`, `reasons -> list[Reason]`.
- `@dataclass(frozen=True) RepoInfo(name: str, merge_methods: tuple[MergeMethod, ...], delete_branch_on_merge: bool, prs: tuple[PullRequest, ...], pr_total: int)`
- `parse_repo(data: dict) -> RepoInfo` (input = `data["repository"]` from the query).

Status rules (first match wins): draft → DRAFT; mergeable or merge_state `UNKNOWN` → CHECKING; mergeable `CONFLICTING` or merge_state `DIRTY` → CONFLICT; check_state in `FAILURE/ERROR` and merge_state != `UNSTABLE` → FAILING; check_state in `PENDING/EXPECTED` → PENDING; `BEHIND` → BEHIND; `BLOCKED` → BLOCKED; `CLEAN/HAS_HOOKS/UNSTABLE` → READY; else BLOCKED.

Reasons (all that apply, in this order): Draft (info); computing mergeability (info); Merge conflicts (error); `Check failed: <name>` per failed check (error, or warning when merge_state `UNSTABLE`); `+N more checks not shown` when `checks_total > len(checks)` (info); `N checks pending` (warning); Changes requested (error) / Review required (warning); Behind base branch (warning); `Blocked by branch protection` when status BLOCKED and no error/warning reason yet (error); `Merge state: X` for unrecognized merge_state (warning).

Tests (one each): every status row; CONFLICT beats FAILING; UNSTABLE+failing → READY with warning; CheckRun in progress → pending; StatusContext parsed; truncated-check reason; review reasons; blocked-with-no-other-reason; merge methods order + only-allowed; parse missing headRef/headRepository/rollup (None-safe).

### Task 4: tracker

**Files:** Create `src/pr_mon/tracker.py`, `tests/test_tracker.py`.

**Consumes:** `RepoInfo`, `PullRequest`, `Status`, `BLOCKED_STATUSES`.
**Produces:**
- `class EventKind(StrEnum)`: `NEW, READY, BLOCKED`
- `@dataclass(frozen=True) Event(kind: EventKind, repo: str, number: int)`
- `class Tracker(records: dict)` — `records` shape `{repo: {"<number>": {"status": str, "seen": bool}}}` (same object passed to `save_state`).
  - `update(repo: RepoInfo) -> list[Event]`
  - `mark_seen(repo: str, number: int) -> bool` (True if it changed)
  - `is_unseen(repo: str, number: int) -> bool`
  - `unseen(repo: str) -> set[int]`
  - `forget(repo: str) -> None`

Rules: unknown PR → NEW, unseen. Known PR whose status changed: to READY → READY event; into BLOCKED_STATUSES from outside → BLOCKED event; event marks unseen. New status CHECKING on a known PR does not overwrite the stored status (avoids READY→CHECKING→READY re-fire). PRs absent from the poll are dropped.

Tests: first poll all NEW; stable poll no events; →READY; →CONFLICT; FAILING→CONFLICT no event; READY→CHECKING→READY no event; closed PR dropped; mark_seen clears; restart (new Tracker on persisted records) quiet for unchanged, fires for changed; forget.

### Task 5: GitHub client

**Files:** Create `src/pr_mon/github.py`, `tests/test_github.py`.

**Consumes:** `parse_repo`, `RepoInfo`, `MergeMethod`.
**Produces:**
- `GitHubError(Exception)`; `NotFoundError`, `AuthError`, `RateLimitError(message, reset_at: datetime)` subclasses.
- `get_token() -> str` — runs `gh auth token`; raises `AuthError` if `gh` missing or non-zero exit / empty output.
- `class GitHubClient(token: str, transport: httpx.AsyncBaseTransport | None = None)`
  - `async fetch_repo(name: str) -> RepoInfo`
  - `async merge(pr_id: str, method: MergeMethod) -> None`
  - `async update_branch(pr_id: str) -> None`
  - `async delete_branch(ref_id: str) -> None`
  - `async aclose() -> None`

POST `https://api.github.com/graphql`. Error mapping: HTTP 401 → AuthError; 403/429 with `x-ratelimit-remaining: 0` or GraphQL error type `RATE_LIMITED` → RateLimitError (reset from `x-ratelimit-reset`, else now+60s); GraphQL error type `NOT_FOUND` → NotFoundError; other GraphQL errors / HTTP errors / transport errors → GitHubError with message.

Tests via `httpx.MockTransport`: query variables (owner/name split) and auth header; parse success; NOT_FOUND; 401; rate-limit header; RATE_LIMITED error; merge sends `mergePullRequest` with method; update sends `updatePullRequestBranch`; delete sends `deleteRef`; mutation error surfaces message; invalid name (no slash) → NotFoundError without request.

### Task 6: screens (modals)

**Files:** Create `src/pr_mon/screens.py`; tests in `tests/test_app.py` (Task 7 covers them through the app).

**Produces:**

- `AddRepoScreen(validate: Callable[[str], Awaitable[str | None]])` → `ModalScreen[str | None]`; `validate` returns an error message or None; format check `owner/name` first.
- `ConfirmScreen(message: str)` → `ModalScreen[bool]` (`y` / `n` / `esc`).
- `ActionMenuScreen(repo: RepoInfo, pr: PullRequest)` → `ModalScreen[Action | None]`. Shows title, `[m] Merge` (or disabled with status reason), `[u] Update branch` only when BEHIND, delete-branch `Checkbox` (value True) only when mergeable and not `delete_branch_on_merge`. `m` with one method dismisses immediately; with several pushes `MergeMethodScreen`.
- `MergeMethodScreen(methods)` → `ModalScreen[MergeMethod | None]` with `s`/`m`/`r` for allowed methods only.

### Task 7: app + cli

**Files:** Create `src/pr_mon/app.py`, `tests/test_app.py`; modify `src/pr_mon/cli.py`.

**Consumes:** everything above.
**Produces:** `PrMonApp(client, config_path: Path, state_path: Path)`; `cli.main()`.

Behavior:
- Layout: `OptionList#repos` left; `DataTable#prs` top right (border title `PRs (50 of N)` when truncated); `Static#details` bottom right; `Header` (sub_title shows last refresh / rate-limit / warnings); `Footer`.
- On mount: load config/state (warnings via `notify`), refresh all, `set_interval(poll_interval)`.
- `refresh_repo(name, attempt=0)`: fetch → tracker.update → save state → re-render; on CHECKING PRs and attempt < 3 → `set_timer(5, ...)` with attempt+1; on `RateLimitError` pause polling until `reset_at`; on other `GitHubError` store per-repo error (badge `⚠`, message in details), keep last data.
- Repo label: `● name (n)` with color green (unseen READY) / red (unseen blocked) / yellow; `⚠ name` on error; plain otherwise.
- PR rows: icon, `#num`, title, author, status (colored). Newest first.
- Seen: when `#prs` has focus and a row is highlighted (or on focus), `tracker.mark_seen` → save → relabel repo.
- `A`: `AddRepoScreen` validating via `client.fetch_repo` (dedupe; store canonical name) → save config → refresh.
- `D` (repos focused): `ConfirmScreen` → remove from config, `tracker.forget`, save both.
- `enter` on PR row: `ActionMenuScreen` → run action in worker: merge (+ delete_branch if chosen and `head_ref_id`; failure → warning notify) or update_branch; errors → error notify; then refresh repo.
- `r` refresh all; `q` quit.
- `cli.main()`: `get_token()` (on AuthError print "pr-mon: <msg>. Run `gh auth login`." to stderr, exit 1), build client, run app with default paths, close client.

Pilot tests (FakeClient with canned RepoInfo and recorded calls, temp config/state paths): repos render with badges; selecting repo fills PR table; focusing PR clears badge; enter → menu shows merge; single-method `m` calls merge; multi-method `m` → `s` calls merge SQUASH; checkbox hidden when auto-delete; checkbox checked → delete_branch called; merge disabled for CONFLICT shows reason; `u` only for BEHIND; `A` adds valid repo and rejects invalid; `D` + `y` removes; fetch error shows ⚠.
